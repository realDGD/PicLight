# 决策：PicLight 的项目 AI 工作流

Status: implemented

## 问题

项目已有源码、测试、设计、修复计划和发布记录，但缺少 AI 的统一读取入口。旧 README 中的测试数量与应用包名称也会误导新任务。仅把过去的修复写进长提示词，会重复读取资料，并混淆历史验证和本次结果。

## 决定

用[根入口](../../../AGENTS.md)保存当前项目约定；三个按任务触发的技能引用[开发指南](../../../docs/development.md)和[验证指南](../../../docs/testing.md)。任务模板保存中断与恢复信息，决策目录只保存会影响以后选择的理由。现有需求与计划保留原位置。

文档检查器读取当前 AI 导航文件，包含新建、尚未跟踪的 Markdown；检查文件链接、项目技能的基础元数据和活动决策状态。验证记录仍按实际执行结果填写，结构检查不会推断需求完成或 GUI 正确。

## 考虑过的替代方案

**单个大型 AGENTS.md。** 查找入口简单，但构建说明、测试地图、历史取舍和任务状态会一起进入上下文；因此只在根入口保留路由与稳定约定。

**完整复制参考仓库的规则。** DeepSeek Harness 的包、平台和发布流程与 PicLight 不同，直接复制会产生不存在的命令和验证要求；因此只采用组织方式。

**只新增更多计划文档。** 可以记录具体任务，却不能解决日常任务的发现与验证选择问题；因此计划继续服务单个任务，长期规则另有入口。

## 影响与代价

每条主要事实有明确维护位置，修改规则或指南后检查相对链接。三个技能需要随项目使用反馈迭代；其效果用任务情景检查，不能仅凭格式验证判断。新增 Python 检查器使用标准库，开发工具要求 Python 3.9 或更新版本。它不检查远程链接、Markdown 锚点、截图显示或事实语义。

参考版本和来源记录在[工作流索引](../../README.md)，不需要为每次任务重新查询参考项目。
