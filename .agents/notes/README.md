# 决策记录

记录以后仍可能被重新讨论的理由和取舍。源码、测试和用户文档说明当前行为；决策记录解释为什么选择它。小型局部修复、机械改名和一般进度更新无需单独建记录。

## 放在哪里

采用 `生命周期/YYYY-MM-DD-主题.md`。目录按首次需要记录时创建，不预建空分类。

| 目录 | 意义 |
| --- | --- |
| `proposed/` | 尚未完整实施的方案，文件写 `Status: proposed` |
| `implemented/` | 已落实的决定，文件写 `Status: implemented` |
| `rejected/` | 已否决的方案，文件写 `Status: rejected` 并说明理由 |
| `archived/` | 已结束且只供历史参考的已实施决定，保留原状态并增加归档日期 |

已有项目 spec 和计划继续留在原目录；需要建立联系时加相对链接，不批量搬迁，也不为它们重新推测实施状态。

## 内容与更新

使用[决策模板](../templates/decision.md)。说明问题、决定或建议、真实考虑过的替代方案、代价与验证依据。不要凭空增加被否决的选项。变更实现路径或命名时同步当前事实，仍保留原来的选择理由。

提议落实后移动到 `implemented/`，同一次变更更新状态、实际决定和引用；部分完成仍保持提议。否决时记录原因。归档内容是历史证据，不作为当前开发要求；以后出现新问题另建当前记录。

任务执行状态使用[任务模板](../templates/task.md)。根入口和各任务中的链接负责发现记录，不维护另一份需要重复更新的全量决策索引。
