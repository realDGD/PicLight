# PicLight 开发与恢复任务

用当前使用问题驱动改动。先读取[项目入口](../../../AGENTS.md)，源码位置和命令按需查[开发指南](../../../docs/development.md)。

## 开始任务

核对用户的最新要求、当前分支和未提交文件。明确用户能观察到的完成条件；已有方案或纠正直接延续，只有会改变实现选择的缺失信息才询问。

按具体行为查拥有状态的代码及整合端，再读相关测试。需要隔离工作区时保留必需的未提交与未跟踪输入；不要只导出 `git diff` 就认为已复制整个工作状态。

## 按问题推进

| 场景 | 做法 |
| --- | --- |
| 使用 bug | 复现原来的错误，追踪实际入口，增加能捕获该错误的回归，再修改承担行为的代码 |
| 新设置或命令 | 明确默认行为、持久化、生效时机和取消/失败后的状态，接入现有命令与设置模型 |
| 异步或大图问题 | 追踪发起、取消、发布和结束的生命周期；读取对应身份、缓存和预算实现 |
| 恢复较长任务 | 从当前任务记录查已完成、剩余验证和下一步，再核对记录后的源码变化 |

多步任务使用[任务模板](../../templates/task.md)保留验收、状态和交接；短任务无需额外建文档。长期取舍按[决策记录规则](../../notes/README.md)记录。

例如“标题栏出现时图片移动”：验收包含 Fit 和手动放大状态下反复显隐，比较画布、缩放和中心；只检查窗口外框不够。按[验证指南](../../../docs/testing.md)选择相关测试和原生场景。

完成时区分实际实现、验证结果和尚未覆盖的使用条件。复制参考截图到需求文档不等于实现截图中的功能；部分完成也不把提议改成已实施。
