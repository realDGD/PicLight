# PicLight 第二批：改善使用流程

状态：设计待确认，尚未实施。源码基线：`1ba3fec`；运行代码与已安装的 `03c0dbb` 一致。

## 目标与来源

用户已选择“按清单推进下一批功能”。范围取自本地 `new_feature/功能清单与实现难度.md` 第 6 节“第二批”，并结合第 2.1、3.2–3.5、4.1、5.1 节的已确认选项。原截图和本机绝对路径不发布；本设计提取可实施的使用行为。

本批覆盖最近打开菜单与主页列表、底部缩略栏、长图顶部起始、幻灯片、键盘平移、缩放锁定、透明棋盘格、目录变动更新策略、拍摄时间排序、稳定随机顺序，以及基础 OCR / 系统实况文本。文件夹授权管理已在 main，本批仅保留其行为与相关回归。桌面贴图属于第三批。

新增控件必须连到持久化、实际行为和当前状态刷新。只提供设置界面或未接到查看器的服务不算完成。

## 约束与既有决定

- macOS 14+；主程序仍用 CLT 编译，复用已核对的图标和 Metal 库；不修改全局 Xcode 选择。
- 保留 GIF / APNG / 动画 WebP 的原始时间轴、三槽预算、独立封面 APNG 修正和 Metal / Quartz 路径。文件夹幻灯片与单个文件的动画播放分别控制。
- 保留源身份、请求代际和窗口生命周期检查；旧扫描、解码、缩略图和分析结果不能覆盖新状态。
- 不弹验证窗口、不抢焦点、不生成测试 App 或 DMG；只做有针对性的无窗口检查，暂不做真实使用验收，不跑完整 Swift 测试。
- 原工作区已归档，旧来源仍可恢复。本批从干净 main 开发，不将旧整树或 stash 套回。
- 本设计不改变默认文件关联，不删除真实照片或写入真实目录授权；实际安装仍使用 `/Applications/PicLight.app`。

## 实现方式与取舍

沿用现有 AppKit 窗口、FolderSession、ViewportState、ThumbnailPipeline 和解码协调器；为最近记录、幻灯片、目录更新协调和图像分析增加边界明确的服务，查看器只负责整合。最近记录使用系统 NSDocumentController；OCR 优先使用系统 VisionKit / Vision。该路径与清单优先复用系统能力的建议一致。

另一个可行选择是应用自行保存最近记录、用 Vision 文字框自行实现全部选字交互。它能统一自定义外观，却需要额外维护记录持久化和选字输入。此批采用系统接口；系统不支持实况文本时保留文字识别与复制的降级路径，不自建选字引擎。重写全部查看器或引入第三方解码 / OCR 库超出此批范围。

以下未由原清单确定的细节是本设计的建议，确认后作为实施依据。

## 使用行为

### 1. 最近打开

- 文件菜单增加“最近打开”和“清空最近记录”；无图片首页显示同一来源的列表，最多 10 项，仅显示文件名和用于区分同名文件的父目录，不预解码原图。
- 设置 → 看图 → 一般增加“记录最近打开”“在首页显示最近打开”“正常退出后清空最近记录”。建议默认分别为关闭、开启、关闭；关闭记录后不新增，显示列表可独立关闭，清空是明确操作。
- 只有用户明确打开并成功显示的文件才写入记录；后台预取、失败、被取消的旧请求和普通翻页不新增。菜单、主页、Finder 和打开面板复用已有打开协调器与授权流程。
- 失效或不可访问文件不在主线程提前遍历。点击后按现有打开失败路径提示，可从最近列表移除；不为记录提前弹授权面板。重命名的恢复由系统最近文档记录能力决定，不自行扫描磁盘找文件。
- 设置变化更新现有首页和菜单；正常应用退出时按策略清空。崩溃或强制结束不承诺执行退出清理。测试注入记录后端，不写真实系统列表。

### 2. 底部缩略栏

- 设置 → 看图 → 外观增加“缩略图位置：左边 / 底部”，默认左边。现有显式开关与选择保持；网格的文件夹树仍在左侧。
- 底部使用虚拟化的横向列表，复用当前窗口的缩略图管线、文件版本、缓存清理与选择回调。只请求可见区域和有界预取带；保留现有 24 MiB 查看器缩略图预算。
- 显式打开底栏占用画布高度，关闭恢复；切换位置只保留一条可见缩略栏。Fit 重新适应剩余区域，手动缩放保持倍率和焦点并合法钳制。底栏以 100 pt 高度为初始实现值，具体内边距交由实现者确定。
- 工具坞、鸟瞰图和信息卡仍锚定实际画布；选中项可见，快速切图的旧缩略图不落入新单元格。隐藏列表退出输入命中和请求。

### 3. 长图顶部起始与缩放锁定

- 设置 → 看图 → 浏览增加“长图从顶部开始”，默认关闭。开启后，显示后宽高比不超过 1:2 的图片在初次打开或明确翻页时适应宽度并对齐顶部；只有显示高度超出画布才对齐，普通图片仍 Fit。
- 缩放锁定是每个查看器窗口的状态，默认关闭，提供菜单与可自定义快捷键，建议默认 ⌘F。锁定时保存图像像素与物理屏幕像素的倍率，跨翻页、不同尺寸和 Retina 屏保持；窗口布局变化不将锁定倍率重新当成 Fit。
- 开启锁定后用户主动缩放会更新锁定倍率。新图的中心默认居中；若长图顶部选项同时开启，只对齐新图顶部，不覆盖锁定倍率。锁定关闭后下一张按普通初始策略。
- 优先级：用户在加载期间主动操作 > 已开启的缩放锁定 > 长图初始策略 > 默认 Fit。更高解码级别发布、动画换帧、目录元数据补齐均不重置视口。
- 旋转和镜像继续为显示变换；对齐与边界按 EXIF 后、显示旋转后的尺寸计算，不修改源文件。

### 4. 键盘平移

- 新增上 / 下 / 左 / 右四个可自定义命令，默认 ⌘方向键；默认每次移动画布对应方向长度的 10%，使用现有平移与钳制模型。
- 图片小于可用画布时不会漂移。命令只在看图且有图时可用；网格、设置、文本编辑以及 OCR 正在选字时保留各自键盘行为，不覆盖现有图片导航和 TIFF 分页键。

### 5. 文件夹幻灯片

- 新增“开始 / 暂停幻灯片”菜单命令及可自定义快捷键，建议 ⇧⌘Return；浏览设置增加间隔，默认 10 秒，合法范围 0.5–3600 秒。
- 每个窗口最多一个计时任务。开始后从当前已显示图片计时；下一张首帧成功显示后再开始下一个完整间隔。慢解码不并发堆积翻页；单个 GIF 的内部帧仍按原时间轴播放，不等待 GIF 播完才翻下一文件。
- 用户手动翻页重置本张计时；末尾按现有循环浏览设置停止或回绕。空目录、单张目录、当前文件解码失败、进入网格、关闭窗口或打开另一目录停止幻灯片；暂停动画不等同于暂停幻灯片。
- 计时使用可注入单调时钟，不用真实睡眠写长耗时测试。界面根据真实状态显示开始 / 暂停。

### 6. 透明棋盘格

- 设置 → 看图 → 浏览增加“显示透明棋盘格”，默认关闭；开启后在图像覆盖区域下绘制棋盘，透明像素透出棋盘，画布其他位置沿用背景。
- Metal 与 Quartz 共用背景几何和配色，考虑 Retina、EXIF、显示旋转、镜像、缩放与原生细节层。先采用画布背景层与透明 Metal 合成，避免为背景修改 shader 或更新预编译资源。
- 棋盘单元使用固定 8 pt 尺寸、随外观刷新颜色；只绘制可见区域，不生成与原图尺寸相同的背景位图。无图、隐藏画布与不透明图片不引入额外整图缓存。

### 7. 目录变动更新策略

- 设置 → 看图 → 浏览增加“忽略 / 立刻更新 / 翻页时更新”，默认立刻更新，保留现有事件合并延迟。
- 忽略：停止自动监听更新；用户明确打开目录、重新加载或改变过滤 / 排序仍生效。
- 立刻更新：沿用现有重扫和同路径替换保护，按文件身份保留当前选择与视口。
- 翻页时更新：监听只标记目录已变。在执行下一张、上一张、首张、末张、随机选择或幻灯片前，先完成一次当前目录刷新，再按刷新后的列表导航；缩略图明确点击按文件身份选择，不能沿用旧索引。
- 刷新期间合并重复扫描，保留导航输入顺序，待执行输入队列最多 32 项，超出后合并同方向重复输入；换目录、关闭和更新策略变化清除旧待处理项。重扫失败不基于残缺的新列表继续导航，沿用错误 / 权限恢复入口。
- 用户取消授权不继续扫描或导航。旧目录迟到结果不能清除新目录的待更新状态或执行旧导航。

### 8. 拍摄时间排序与随机顺序

- 在现有排序选项中增加“拍摄时间”“随机顺序”，保留其他排序。拍摄时间只在选中该排序时按需读取 ImageIO 属性，不解码像素；限制并发并支持生命周期失效。
- 日期优先 EXIF 原始拍摄时间及其时区，缺失时用数字化时间再到 TIFF 时间。带时区按绝对时间比较；无时区按 UTC 解释该墙上时间以避免设备时区改变顺序，界面不冒称知道原拍摄时区。格式损坏视为缺失。
- 有拍摄时间的条目按升降序排列，缺失始终排末尾，平局用自然文件名与稳定身份比较。异步补齐后保持当前文件，不重开图片；更换排序 / 目录拒绝旧批次发布。
- 随机顺序在每个目录会话中生成一次，重扫和元数据更新保持既有条目的相对顺序，新增条目随机插入，删除条目移除。重新选择随机排序或重新打开目录建立新排列；随机模式下方向控件禁用。“随机一张”继续是独立命令。
- 随机状态仅保留当前目录，不为所有访问过的文件夹累积内存；测试注入确定性随机源。

### 9. 基础 OCR 与系统交互

- 看图菜单和工具坞提供“识别图中文字”，以及识别成功后的“复制全部文字”。设置 → 看图 → 一般增加自动识别和显示 OCR 按钮，建议默认关闭、开启。所有分析在本机系统框架内进行，不新增第三方服务。
- 优先采用 ImageAnalyzer 和 ImageAnalysisOverlayView：提供图内选字 / 复制，以及设备支持时的系统主体交互。运行时检查支持情况；不支持系统覆盖层时，使用 Vision 识别并提供文字查看与复制，不承诺相同选字体验。
- 基于现有有界显示代理构建最长边 2048 像素的分析输入，不为了 OCR 重新完整解码超大原图。小字质量可能受代理限制；不增加全分辨率 OCR 模式。本批不提供自定义文字编辑、主体蒙版保存或导出。
- 自动分析只用于静态图片和当前 TIFF 页；播放中的动画不逐帧分析。手动分析动画时暂停在当前已显示帧，只复制当前租约并生成有界输入，保留原动画时间轴的暂停 / 恢复语义；不缓存整个动画。全尺寸帧复制的临时成本单独记录，不称为 2048 输入的内存上限。
- 识别输入先统一当前显示旋转 / 镜像；视口变化只更新覆盖层内容区域。文件版本、页码、显示变换或当前请求变化使旧结果失效；关闭窗口和切图立即清除覆盖层。不可取消的系统工作限制为每窗口一个实际请求及一个最新等待输入，不能仅依赖 Task.cancel。
- 默认看图输入路由继续有效；仅系统命中到可交互内容或明确的识别按钮时由覆盖层处理点击。滚轮 / 捏合送往画布，选字期间保留系统选择与复制行为。空白、隐藏或过期覆盖层不拦截事件。
- 无文字、无设备支持、失败和被取消分别呈现当前状态；不弹独立结果窗口，不把“无文字”当作读取失败。

## 默认值与设置迁移

新增设置使用新键，不重写旧设置。左侧缩略栏、立即目录更新、10 秒幻灯片间隔为默认值；长图顶部、棋盘格、缩放锁定、自动 OCR 默认关闭。最近记录默认关闭，主页列表与 OCR 按钮默认开启但只有对应内容 / 能力时出现。

快捷键迁移补入新增命令时必须区分旧版本尚无该命令与用户主动“全部清空”；不能重新填回已清空的旧绑定。新绑定冲突时不覆盖用户设置，仍可从快捷键页配置。

## 实施顺序与代码边界

1. 最近记录与菜单 / 首页，新增独立记录服务；更新 AppDelegate、MainMenuBuilder、EmptyStateView 和设置。
2. 目录更新协调与排序，扩展 FolderItem / FolderScanner / FolderSession；查看器与网格共用排序和当前目录身份。
3. 视口策略、键盘命令、棋盘背景，保留现有 RenderImage、原生细节和两条渲染路径。
4. 横向缩略栏及位置切换，复用缩略图请求 / 清理，统一左右栏与底栏的画布区域计算。
5. 独立幻灯片控制器，整合导航、首帧完成、错误与关闭清理。
6. 图像分析服务及系统覆盖层，整合用户手动触发、自动策略、变换和输入路由；最后集中核对设置刷新与命令可用状态。

新增服务和纯状态尽量独立于大型 ViewerViewController；保留现有整合点，不借此重写整个查看器。具体私有类型名称、行距及辅助方法由实现者按实际代码选择；上述可观察行为和预算是验收依据。

## 定向验证与交付边界

每组添加能区分正确 / 错误行为的定向检查，SwiftPM 构建与测试串行执行。重点覆盖：

- 最近记录只记成功且明确的打开，关闭记录 / 退出清空 / 失效文件，不写真实系统记录。
- 目录更新三种模式、延迟扫描后导航、同路径替换、授权取消和快速换目录；拍摄时间缺失、时区、稳定随机与新文件。
- 长图初始策略和锁定优先级、解码期间手动视口、Retina 迁移、旋转 / 镜像、布局变化与边界钳制。
- 底部与左侧位置切换的画布几何、唯一输入命中、可见项预算、缩略图迟到与缓存清理；网格树保持原位置。
- 幻灯片的虚拟时钟、慢解码、末尾回绕、失败与关闭，证明不改变 GIF 帧时间轴。
- 棋盘格在离屏像素检查中的 Metal / Quartz 一致性与透明 / 不透明图像。
- OCR 注入后端的旧结果拒绝、实际并发上限、代理输入尺寸、无文字 / 不支持 / 失败；覆盖层几何和事件路由。
- 旧设置、快捷键空快照、三槽动画与 APNG 首帧相关回归，以及文档与预编译资源一致性。

不因提交而重复运行同一证据，也不把无窗口检查说成原生使用已验收。CLT 编译只生成可执行输出；本批完成后记录实际命令、选中数量、失败 / 排除项与 Agent Note。软件安装和真实 UI 验收继续按之后的明确任务安排，不为本设计提前生成包。

## 系统接口依据

- [Apple：NSDocumentController.noteNewRecentDocumentURL](https://developer.apple.com/documentation/appkit/nsdocumentcontroller/notenewrecentdocumenturl(_:))：非 NSDocument 应用需要接到自己的打开委托。
- [Apple：ImageAnalysisOverlayView](https://developer.apple.com/documentation/visionkit/imageanalysisoverlayview)：支持文本、主体交互与自定义内容矩形；不是只能用于 NSImageView。
- [Apple：ImageAnalyzer](https://developer.apple.com/documentation/visionkit/imageanalyzer)：异步分析和运行时支持检查。
- 本机 CLT SDK 的 VisionKit Swift 接口已核对：ImageAnalyzer、macOS 覆盖视图、contentsRect / contentView 委托及系统键盘事件委托均可用；这只是 API 可行性证据，不是实际系统选字体验的验证。
