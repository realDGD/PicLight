## 2. What was automated in this pass

The original checklist had a large "requires a human" section. Most of it turned
out to be automatable through AppKit itself, the packaged bundle and the sources.

| Was manual or weak | Now covered by |
| --- | --- |
| "Verify 1/2/3 viewer windows" | `WindowArchitectureTests` creates real viewers and counts windows **by type**, not by `NSApp.windows.count` |
| "Drawer/hover/minimap must not add windows" | Same file drives every chrome surface and asserts no new window, `NSPanel` or child window |
| Window style policy | Positive assertions on the real window (`titled`, `closable`, `miniaturizable`, `resizable`, `fullSizeContentView`), `tabbingMode`, standard traffic-light buttons. The plan's `styleMask.contains(.borderless)` assertion was removed as meaningless — `.borderless.rawValue == 0` makes it always true |
| "Native tabs must not be used" | Source scan for `addTabbedWindow`/`tabGroup`/`tabbedWindows` plus the runtime flag, now also enforced inside `ViewerWindow` itself |
| Immersive Mode | Window frame, screen, identity and style mask proven unchanged while chrome policy changes; starts hidden; temporary hover reveal works; a parked pointer does not re-reveal |
| Native Full Screen | The menu provably uses the standard `toggleFullScreen:`, not a custom command; `fullScreenPrimary` is set; immersive never sets the full-screen style bit; the two states are independent. The actual Space transition stays manual |
| "10,000 file folder" | `LargeFolderStressTests`: scan, sort, non-recursion, no image-body inspection, lazy dimension sort, bounded decode requests, bounded thumbnail requests, bounded in-flight tasks while scrubbing |
| "Stale decode must not win" | `RapidSwitchCancellationTests`: A→B→C→D→E publishes only the newest; 500 forward + 500 backward switches stay correct and bounded |
| Cache and memory behavior | `CacheInvariantTests`: exact cost formula, memory-pressure purge keeps the current image, caches are independent, release stops publication, RSS trend measured (no threshold) |
| Folder changes while open | `FolderDynamicsTests`: add/remove/rename, non-recursive watching, debounce, and a descriptor-leak regression test for the earlier double-close bug |
| Opening paths | `OpenPathTests` drives the real `AppEnvironment`: one/several files, reuse-current, configured default and explicit inverse, unsupported files, corrupt files, declared Finder types |
| Trash behavior | `TrashAndImmutabilityTests`: system API, smart next/previous, empty state, deterministic failure path, SHA-256 proof that viewing never rewrites a source |
| Animation lifecycle | `AnimationLifecycleTests`: autoplay, pause/resume, restart at frame 0, animated WebP parity, at most one clock, finite vs infinite loops |
| Appearance structure | `SourcePolicyTests`: glass chosen by availability guard matching the running OS, system views only, no hand-built blur, canvas never behind material, Follow System forces nothing, Reduce Motion/Transparency policies verified on both branches |
| "No network dependency" | Source scan proving no `URLSession`/`Network`/URL literals exist; real offline launch stays manual |
| "No libwebp runtime" | Source scan plus `otool -L` on the shipped binary |
| DMG / artifact checks | `scripts/verify-release.sh`: 19 checks over bundle layout, versions, document types, signature, dependencies, deployment target, DMG contents and a mounted-volume acceptance run |

## 3. Defects found by the new automation

| # | Root cause | Production bug? | Fix | Regression coverage |
| --- | --- | --- | --- | --- |
| 1 | The scanner returns resolved paths (`/private/var/…`) while an opened URL may keep the symlinked spelling (`/var/…`). Identity and selection compared raw strings, so opening a file through a symlinked path could select the **first** folder entry instead of the requested file | Yes — wrong image shown for `/tmp`, `/var` and symlinked folders | Canonicalize the directory once in `open(url:)`; `select(url:)` and `setItems` fall back to a folder-scoped filename match | `FolderDynamicsTests`, `OpenPathTests.testOpeningSeveralFilesCreatesOneViewerEach` |
| 2 | Preload entries cleared themselves from a nested task, so cleanup lagged behind rapid switching: 370 entries in flight after 1000 switches | Yes — unbounded-ish work accumulation while scrubbing | Actor-isolated preload with `defer` cleanup; neighbours outside the new set are cancelled immediately | `RapidSwitchCancellationTests` (asserts ≤ 3 in flight) |
| 3 | An empty folder wrote `""` into `errorMessage` | Yes — an empty folder looked like a failure | Explicit `applyEmptyState()` | `TrashAndImmutabilityTests` |
| 4 | A failed Move to Trash reported only through the inline label, leaving the observable state silent | Yes — inconsistent error reporting | Single `presentTransientError` path used by both the label and the state | `TrashAndImmutabilityTests.testAFailedTrashKeepsTheCurrentSelectionAndReportsWhy` |
| 5 | `NSWindow.allowsAutomaticWindowTabbing = false` lived only in the app delegate | Weakness — the invariant depended on delegate timing | Also enforced by `ViewerWindow` itself | `WindowArchitectureTests.testNativeTabbingIsDisabledOnTheWindowAndAppWide` |

Test-side corrections worth noting (not product bugs): the plan's `.borderless`
assertion was meaningless because that option's raw value is 0; three of my own
first-draft assertions were wrong (clamping legitimately moves the focal point at
image edges, `dy` must be divided by the scaled height, and a corrupt fixture was
the last item so "next" could not move). Each was corrected against real behavior
rather than by weakening the check.

## 5. Clean-room rebuild

The final pass deletes `.build` and `dist`, then rebuilds from the committed tree
and re-runs every gate above. Results are recorded in the commit that accompanies
this document and summarised in `v0.1-checklist.md`.

## 6. Environment limits (why some items stay manual)

This machine cannot capture the screen (`list_displays` is empty; `screencapture`
is unavailable to the agent), so no automated check here can judge **how
something looks**. Structure, behavior, geometry, lifecycle and artifacts are all
verifiable and are verified; visual quality and interactive feel are not.
